# แผน เฟส 2: ฝากไฟล์ชั่วคราว (Drop)

วันที่: 2026-10-25
สถานะ: ร่าง รอเคาะคำถามท้ายเอกสาร
ต่อจาก: [2026-10-24-public-api.md](2026-10-24-public-api.md)

## เป้าหมาย

ให้โปรแกรมอื่นส่งไฟล์มาฝากด้วย API key แล้วได้ **ลิงก์สำหรับโหลด** กลับไปทันที
ไฟล์จะ **ลบตัวเองเมื่อหมดเวลา** (หรือเมื่อโหลดครบจำนวนครั้ง ถ้าตั้งไว้) เช่น
bot สร้างรายงานแล้วส่งลิงก์ให้คนในแชต ลิงก์ใช้ได้ 24 ชั่วโมงแล้วหายไปเอง

คนที่ล็อกอินอยู่ก็ฝากผ่านหน้าเว็บได้ด้วย (ลากไฟล์ใส่ → ได้ลิงก์)

## ของที่มีอยู่แล้วและจะใช้ต่อ

- API key, scope, เพดานขนาดอัปโหลดต่อ key, rate limit (เฟส 1)
- การรับไฟล์แบบ stream ลงดิสก์ (`upload-service.ts`, `/api/v1/files/raw`)
- หน้าแชร์สาธารณะ `/share/[id]` ที่ดูรูป วิดีโอ เสียง และโหลดไฟล์ได้อยู่แล้ว
- รหัสลิงก์สุ่ม 18 ไบต์ (`createShareId`) เดาไม่ได้

สิ่งที่ยังไม่มี: **งานที่รันเองเป็นรอบๆ** ตอนนี้ถังขยะถูกล้างตอนผู้ใช้เปิดรายการไฟล์เท่านั้น
ไฟล์ฝากต้องถูกลบตรงเวลาแม้ไม่มีใครเข้าเว็บ จึงต้องเพิ่มตัวจับเวลาใน `instrumentation.ts`

## การออกแบบ

### 1. เก็บไฟล์ไว้ที่ไหน (เคาะแล้ว 2026-10-25)

แยกไว้ใน **โฟลเดอร์ฝากไฟล์** โฟลเดอร์เดียว แต่ละไฟล์อยู่ในโฟลเดอร์ย่อยชื่อสุ่มของตัวเอง:
`<โฟลเดอร์ฝากไฟล์>/<dropId>/file` (ชื่อไฟล์จริงเก็บในฐานข้อมูล ไม่ใช้เป็นชื่อบนดิสก์)

- **ค่าเริ่มต้น** มาจาก env `DROPS_DEFAULT_DIR` ซึ่ง docker-compose ตั้งเป็น `/host_root${NAS_HOST_DIR}/drops`
  (บน radxa = `/mnt/drops`) ถ้าไม่ได้ตั้ง ใช้ `STORAGE_INTERNAL/drops`
- **ADMIN เปลี่ยนได้ทีหลัง** และเมื่อเปลี่ยน ไฟล์ฝากที่ยังไม่หมดอายุทั้งหมด **ย้ายตามไปด้วย**
  - ไฟล์ใหม่ไปที่โฟลเดอร์ใหม่ทันที ไฟล์เก่าย้ายทีละรายการอยู่เบื้องหลัง
  - แต่ละแถวในฐานข้อมูลจำว่าไฟล์อยู่ที่ไหนจริง (`baseDir`) ระหว่างย้าย ลิงก์ของไฟล์ที่ยังไม่ถึงคิวจึงโหลดได้ตามปกติ
  - รายการที่ค้าง (เช่น กำลังอัปโหลดอยู่ตอนเปลี่ยน) ตัวกวาดรอบถัดไปจะย้ายให้
  - ย้ายเสร็จแล้ว ลบโฟลเดอร์เก่าเฉพาะเมื่อว่างเปล่า
- **กันพลาด:** โฟลเดอร์ใหม่ต้องยังไม่มี, ว่างเปล่า, หรือเคยเป็นโฟลเดอร์ฝากไฟล์มาก่อน (มีไฟล์ป้าย `.webnas-drops`)
  ต้องอยู่บนดิสก์ถาวร และห้ามเป็นตัวโฟลเดอร์เก็บข้อมูลหลักเอง เช่น `/mnt` ป้องกันกรณีเลือก `/mnt`
  แล้วตัวกวาดไปลบของคนอื่น ตัวกวาดลบเฉพาะโฟลเดอร์ย่อยที่ชื่อเป็นรูปแบบ dropId เท่านั้น
- โฟลเดอร์ฝากไฟล์ถูกล็อกจากหน้าจัดการไฟล์ (เหมือนโฟลเดอร์ระบบ) ไม่มีใคร รวมถึง ADMIN เข้าไปแก้ไฟล์ข้างในตรงๆ ได้

เหตุผล:
- ไฟล์ชั่วคราวไม่ปนกับไฟล์จริงของผู้ใช้ และตอนลบจะลบทั้งโฟลเดอร์ `<dropId>` ไม่มีทางไปลบไฟล์อื่นที่บังเอิญชื่อซ้ำ
- เลือกดิสก์ได้ ไม่ต้องไปกินพื้นที่ดิสก์ระบบที่ `/app/data` อยู่
- ผู้ใช้ไม่ต้องมีสิทธิ์ในโฟลเดอร์นั้น ระบบเป็นคนจัดการเอง

### 2. ฐานข้อมูล

```prisma
model Drop {
  id            String    @id                    // random id, also the public link id
  fileName      String                           // original name, shown on the page
  size          BigInt
  mimeType      String?
  expiresAt     DateTime
  maxDownloads  Int?                             // null = unlimited
  downloads     Int       @default(0)
  createdAt     DateTime  @default(now())
  deletedAt     DateTime?                        // file removed, row kept briefly for the list

  user          User      @relation(fields: [userId], references: [id], onDelete: Cascade)
  userId        String
  keyId         String?                          // which API key uploaded it, if any

  @@index([expiresAt])
  @@index([userId])
  @@map("drops")
}
```

ไม่ใช้ตาราง `ShareLink` เดิม เพราะ ShareLink ผูกกับ path ในพื้นที่ของผู้ใช้และตรวจสิทธิ์เจ้าของทุกครั้ง
แต่ไฟล์ฝากอยู่นอกพื้นที่นั้น จะใช้ **หน้าตาและตัวเล่นสื่อ** ของหน้าแชร์ซ้ำ แต่แยกเส้นทางกัน

### 3. API (ต้องมี scope ใหม่ `drop`)

| Method | Path | ทำอะไร |
|---|---|---|
| PUT | `/api/v1/drops?name=report.pdf&expiresIn=24h&maxDownloads=3` | body คือไฟล์ ตอบ `{ id, url, downloadUrl, expiresAt }` |
| POST | `/api/v1/drops` | แบบ multipart (`file`, `expiresIn`, `maxDownloads`) |
| GET | `/api/v1/drops` | รายการที่ตัวเองฝากไว้และยังไม่หมดอายุ |
| DELETE | `/api/v1/drops/:id` | ลบก่อนหมดเวลา |

- `expiresIn` รับ `30m`, `24h`, `7d` ค่าเริ่มต้น 24 ชั่วโมง เพดานตามที่ ADMIN ตั้ง
- เพดานขนาดไฟล์ของ key ยังใช้เหมือนเดิม และเพิ่ม **โควตารวมต่อผู้ใช้** (ผลรวมไฟล์ฝากที่ยังไม่หมดอายุ)
- `url` = หน้าเว็บ `/d/<id>` (ดูตัวอย่างได้), `downloadUrl` = โหลดตรงสำหรับ `curl`/`wget`

### 4. ฝั่งคนโหลด (ไม่ต้องล็อกอิน)

- `/d/<id>` หน้าแสดงชื่อไฟล์ ขนาด เวลาที่เหลือ ปุ่มโหลด และพรีวิวรูป วิดีโอ เสียง
- `/api/public/drop/<id>/download` โหลดตรง รองรับ `Range` (โหลดต่อได้)
- หมดอายุ / โหลดครบ / ถูกลบ → ตอบ 404 ทันที แม้ไฟล์จริงยังไม่ถูกลบ
- นับครั้งโหลดเมื่อเริ่มส่งไฟล์ตัวเต็ม (ไม่นับคำขอแบบ Range ที่ต่อจากครั้งก่อน และไม่นับการเปิดดูหน้าเว็บ)
- ใช้ rate limit ต่อ IP แบบเดียวกับหน้าแชร์ (ตอนนี้ได้ IP จริงแล้วหลังแก้ Cloudflare)

### 5. ตัวลบไฟล์หมดอายุ

- `instrumentation.ts` → `register()` เริ่มตัวจับเวลาทุก 5 นาที (เฉพาะ runtime Node) และรันหนึ่งรอบตอนเปิดเครื่อง
- ลบโฟลเดอร์ `<dropId>` ของรายการที่หมดอายุหรือโหลดครบ แล้วตั้ง `deletedAt`; ลบไม่สำเร็จจะลองใหม่รอบหน้า
- ลบแถวที่ `deletedAt` เก่ากว่า 7 วันทิ้ง
- กวาดโฟลเดอร์ในโฟลเดอร์ฝากไฟล์ที่ไม่มีแถวในตาราง (เช่น อัปโหลดค้างตอนเครื่องดับ)

### 6. หน้าเว็บสำหรับเจ้าของ

- เมนู **Drops** ในแถบข้าง: รายการไฟล์ที่ฝาก เวลาที่เหลือ จำนวนครั้งที่โหลด ปุ่มคัดลอกลิงก์ ปุ่มลบ
- ลากไฟล์ใส่เพื่อฝาก เลือกเวลาหมดอายุและจำนวนครั้ง → ได้ลิงก์
- หน้า Setting ของ ADMIN: โฟลเดอร์ฝากไฟล์, เวลาหมดอายุสูงสุด, โควตาต่อผู้ใช้
- ส่วนสร้าง API key: เพิ่มช่องเลือกสิทธิ์ `drop`

## คำถามที่ต้องเคาะก่อนเริ่ม

1. **เก็บไฟล์ที่ไหน:** โฟลเดอร์ฝากไฟล์แยกที่ ADMIN ตั้ง (ข้อเสนอ) หรือเก็บในโฟลเดอร์ของผู้ใช้เองแล้วโผล่ในหน้าจัดการไฟล์?
   ถ้าเลือกแบบแยก บน radxa ควรตั้งเป็น `/mnt/drops` หรือที่อื่น?
2. **ให้คนไม่ล็อกอินฝากไฟล์ได้ไหม:** ร่างนี้ **ยังไม่ทำ** (เสี่ยงโดน spam และดิสก์เต็ม) ให้เฉพาะ API key กับคนที่ล็อกอิน
3. **ค่าเริ่มต้น:** หมดอายุเริ่มต้น 24 ชั่วโมง, นานสุด 7 วัน, โควตารวมต่อผู้ใช้ 10 GB — โอเคไหม?
4. **ใส่รหัสผ่านให้ลิงก์ได้ไหม:** ร่างนี้ยังไม่ทำ (ลิงก์สุ่มยาวเดาไม่ได้อยู่แล้ว) เพิ่มทีหลังได้
5. GUEST ฝากผ่านหน้าเว็บได้ไหม: ร่างนี้ **ไม่ได้** (เหมือนกับที่ GUEST สร้าง API key ไม่ได้)

หมายเหตุ: ผ่าน Cloudflare Free ไฟล์ต่อครั้งยังติดเพดาน 100 MB เหมือนเฟส 1
