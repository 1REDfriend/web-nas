# แผน: ลิงก์รับไฟล์ที่คนส่งดูและโหลดไฟล์ได้ด้วย

วันที่: 2026-11-08
สถานะ: ทำเสร็จ 2026-11-08 ยังไม่ขึ้นระบบ
ต่อจาก: [2026-10-27-inbox-and-paste.md](2026-10-27-inbox-and-paste.md) ส่วน A (Drop request)

## เป้าหมาย

ตอนนี้ลิงก์รับไฟล์ (`/u/<ชื่อลิงก์>`) ใช้ได้ทางเดียว คนอื่นส่งไฟล์เข้ามา แล้วเจ้าของลิงก์เป็นคนเดียวที่โหลดได้
อย่างมากคนส่งก็เห็นแค่ชื่อไฟล์ (ตัวเลือก "Show the names of received files")

รอบนี้ให้เจ้าของเลือกได้ว่าคนที่เปิดลิงก์จะ **เห็นและโหลดไฟล์** ที่ส่งเข้ามาได้แค่ไหน
ลิงก์ที่สร้างใหม่เริ่มที่ "เห็นและโหลดได้ทุกไฟล์" ใครอยากให้ส่งได้อย่างเดียวก็เลือกเปลี่ยนได้

ตัวอย่างที่ใช้จริง

- ส่งการบ้าน: นักเรียนส่งได้อย่างเดียว ไม่เห็นงานของเพื่อน (แบบเดิม)
- ส่งรูปงานแต่ง: แขกอัปรูปแล้วเห็นรูปที่ทุกคนส่งมา โหลดกลับไปได้
- ส่งไฟล์ให้ลูกค้าตรวจ: คนส่งเห็นเฉพาะไฟล์ที่ตัวเองส่ง จะได้เช็กว่าส่งครบไหม และโหลดกลับมาดูได้

## B1. โหมดของลิงก์

แทนช่องติ๊ก `showReceived` ด้วยค่าเดียวชื่อ `shareMode` มี 4 แบบ

| ค่า | คนเปิดลิงก์เห็นอะไร | โหลดได้ไหม |
|---|---|---|
| `none` | ไม่เห็นอะไรเลย ส่งได้อย่างเดียว | ไม่ได้ |
| `names` | ชื่อ ขนาด เวลาของทุกไฟล์ (เหมือน `showReceived` เดิม) | ไม่ได้ |
| `own` | เฉพาะไฟล์ที่ตัวเองส่งจากเบราว์เซอร์นี้ | ได้ |
| `all` (ค่าเริ่มต้นของลิงก์ใหม่) | ทุกไฟล์ที่ลิงก์นี้ได้รับ | ได้ |

- ลิงก์เก่าคงพฤติกรรมเดิม: ที่เปิด `showReceived` อยู่ย้ายเป็น `names` ที่เหลือเป็น `none` ไม่มีลิงก์เก่าไหนถูกเปิดให้โหลดเอง
- ถ้าลิงก์มีรหัสผ่าน ต้องใส่รหัสก่อนถึงจะเห็นรายการหรือโหลดได้ (ใช้ cookie ปลดล็อกตัวเดิม)
- ในโหมด `all` ให้เลือกเพิ่มได้ว่าจะโชว์ชื่อคนส่งในรายการด้วยไหม (`showSenders` ค่าเริ่มต้น ไม่โชว์)
- ไฟล์ยังอยู่ได้ตามเวลา "เก็บแต่ละไฟล์ไว้" ของลิงก์ หมดเวลาก็หายไปจากรายการเอง เหมือนเดิม
- เจ้าของลบไฟล์ไหนทิ้ง ไฟล์นั้นก็หายจากหน้าลิงก์ทันที

## B2. "ไฟล์ของฉัน" รู้ได้ยังไง (โหมด `own`)

คนส่งไม่ได้ล็อกอิน เลยต้องจำด้วยเบราว์เซอร์

- ตอนส่งไฟล์แรก เซิร์ฟเวอร์ออก cookie `wn_req_me_<id ลิงก์>` เป็นค่าสุ่มยาว ๆ (HttpOnly, อายุเท่าลิงก์หรือ 30 วัน)
- เก็บแค่ค่า hash ของ cookie ไว้กับแต่ละ Drop ที่ส่งเข้ามา (คอลัมน์ใหม่ `sender_key_hash`)
- ตอนเปิดหน้าลิงก์ เทียบ hash กับ cookie แล้วโชว์เฉพาะไฟล์ที่ตรง

ข้อจำกัดที่ต้องบอกบนหน้าเว็บ: เปลี่ยนเครื่อง เปลี่ยนเบราว์เซอร์ หรือล้าง cookie แล้วจะไม่เห็นไฟล์เก่า
ถ้าอยากให้ข้ามเครื่องได้ ค่อยเพิ่ม "รหัสคนส่ง" ที่พิมพ์เองทีหลัง (ไม่อยู่ในรอบนี้)

## B3. การโหลดไฟล์จากหน้าลิงก์

ไฟล์ที่รับมาเป็น Drop อยู่แล้ว และ Drop ทุกตัวมีหน้า `/d/<dropId>` ของตัวเอง
ถ้าเอา dropId ไปโชว์บนหน้าลิงก์ตรง ๆ คนที่เห็นก็จะได้ลิงก์ `/d/...` ติดมือไปด้วย
พอเจ้าของเปลี่ยนโหมดกลับเป็น `none` ลิงก์ `/d/...` ที่หลุดไปแล้วก็ยังโหลดได้จนไฟล์หมดอายุอยู่ดี

**ข้อเสนอ:** โหลดผ่านเส้นทางของลิงก์รับไฟล์เท่านั้น

- `GET /api/public/drop-requests/<ชื่อลิงก์>/files/<fileId>` ตรวจทุกครั้งว่า
  ลิงก์ยังใช้ได้ ปลดล็อกแล้ว โหมดยังอนุญาต ไฟล์นี้เป็นของลิงก์นี้จริง และ (โหมด `own`) เป็นไฟล์ของ cookie นี้
- `fileId` เป็นรหัสสุ่มอีกตัวที่ใช้กับหน้าลิงก์อย่างเดียว ไม่ใช่ dropId (คอลัมน์ใหม่ `share_id` บน Drop)
  เจ้าของเปลี่ยนโหมดเมื่อไร การโหลดผ่านหน้าลิงก์ก็หยุดทันที
- ใช้ตัวส่งไฟล์เดิม `createDownloadResponse` รองรับโหลดต่อ (Range) และพรีวิวรูป/วิดีโอ/เสียงแบบหน้า share link
- นับยอดโหลดลงช่อง `downloads` ของ Drop เดิม เจ้าของจะได้เห็นว่ามีคนโหลดกี่ครั้ง
- rate limit ต่อ IP ตัวเดียวกับหน้า share link (`assertShareRateLimit`)
- หน้า `/d/<dropId>` ของไฟล์ที่รับมา ยังใช้ได้เหมือนเดิมสำหรับเจ้าของที่อยากส่งต่อเอง

## B4. กันลิงก์กลายเป็นที่ฝากไฟล์สาธารณะ

โหมด `all` คือใครมีลิงก์ก็ทั้งอัปทั้งโหลดได้ ถ้าลิงก์หลุดไปที่สาธารณะ เซิร์ฟเวอร์ที่บ้านอาจกลายเป็นที่แจกไฟล์ผิดกฎหมายหรือไวรัส
จึงต้องมีหลายชั้น

- ADMIN มีสวิตช์ในหน้า Drop limits ว่าจะอนุญาตโหมด `own` และ `all` ไหม (ค่าเริ่มต้น อนุญาตทั้งสองแบบ)
  ถ้า ADMIN ปิด `all` ลิงก์ใหม่จะเริ่มที่ `own` และลิงก์ที่ใช้ `all` อยู่จะเห็นแค่ชื่อไฟล์ จนกว่าจะเปิดกลับ
- ตอนเลือก `all` หน้าฟอร์มแนะนำให้ตั้งรหัสผ่าน และเตือนว่าใครมีลิงก์ก็โหลดได้ทุกไฟล์
- ADMIN เห็นโหมดของทุกลิงก์ในรายการ "All request links" และกดหยุดลิงก์ได้อยู่แล้ว
- ยอดโหลดต่อลิงก์ต่อวันมีเพดาน ADMIN ตั้งเองได้ ค่าเริ่มต้น 2,000 ครั้ง ใส่ 0 = ไม่จำกัด
  เกินแล้วหยุดโหลดจนถึงเที่ยงคืน (นับตามวัน UTC) ส่งไฟล์ยังได้
- หน้า `/u/...` ยังใส่ `noindex` เหมือนเดิม

## B5. หน้าตา

**หน้าคนส่ง (`/u/<ชื่อลิงก์>`)**

- ส่วนบนเหมือนเดิม: หัวข้อ คำอธิบาย ช่องชื่อ ที่ลากไฟล์
- ข้างล่างมีรายการไฟล์ (โหมด `own` หัวข้อ "ไฟล์ที่คุณส่ง" / โหมด `all` หัวข้อ "ไฟล์ในลิงก์นี้")
  แต่ละแถวมี ชื่อ ขนาด อีกนานแค่ไหนจะถูกลบ ปุ่มโหลด และปุ่มพรีวิวถ้าเป็นรูป/วิดีโอ/เสียง
- ส่งไฟล์เสร็จ ไฟล์ใหม่โผล่ในรายการทันทีโดยไม่ต้องรีเฟรช

**หน้าเจ้าของ (Settings → Drops → Receive)**

- ช่องติ๊ก "Show the names of received files" กลายเป็นตัวเลือก "Who can see received files" 4 แบบตามตาราง B1
- การ์ดของลิงก์มีป้ายบอกโหมด เช่น "Anyone with the link can download"

## B6. ฐานข้อมูล

```prisma
model DropRequest {
  // แทน showReceived
  shareMode   String  @default("none") @map("share_mode")    // none | names | own | all
  showSenders Boolean @default(false) @map("show_senders")   // only used with "all"
}

model Drop {
  shareId       String? @unique @map("share_id")          // id used on the request page, never the drop id
  senderKeyHash String? @map("sender_key_hash")           // sha256 of the sender's browser cookie ("own" mode)
}
```

migration (`20261108000000_drop_request_sharing`): เพิ่มคอลัมน์อย่างเดียว ไม่ลบอะไร
radxa อัปเดตฐานข้อมูลด้วย `prisma db push` ซึ่งไม่ยอมทำอะไรที่ทำให้ข้อมูลหาย จึงเก็บ `show_received` ไว้
และให้ `share_mode` เป็นค่าว่างได้: ค่าว่าง = ลิงก์ที่สร้างก่อนมีโหมด ใช้ `names`/`none` ตาม `show_received` เดิม
ลิงก์เก่าจึงไม่ถูกเปิดให้โหลดเอง

ตารางนับยอดโหลดรายวันอยู่บน `drop_requests` เอง (`download_day`, `download_count`) นับแบบ UPDATE ทีเดียวกันโหลดพร้อมกันจนเกิน

## B7. API

| ใคร | Method / Path | เปลี่ยนอะไร |
|---|---|---|
| เจ้าของ | `/api/v1/drops/requests` | รับ/ส่ง `shareMode`, `showSenders` แทน `showReceived` (ยังรับ `showReceived` ไว้ช่วงหนึ่ง แปลงเป็น `names`/`none`) |
| คนส่ง | GET `/api/public/drop-requests/<link>` | `received` มี `fileId`, `previewKind` และ `sender` (ถ้าโหมดเปิด) |
| คนส่ง | GET `/api/public/drop-requests/<link>/files/<fileId>` | ใหม่: โหลด/พรีวิวไฟล์ |
| คนส่ง | อัปโหลดทั้งแบบก้อนเดียวและแบบแบ่งชิ้น | ออก cookie `wn_req_me_<id>` และเก็บ hash ไว้กับ Drop |
| ADMIN | `/api/admin/drops` | `requests.settings` เพิ่ม `allowOwn`, `allowAll`, `dailyDownloads` (0 = ไม่จำกัด) |

## ขั้นตอน

1. **ฐานข้อมูล + โหมด** — คอลัมน์ใหม่, migration ย้าย `showReceived`, ตรวจค่า `shareMode` ตามที่ ADMIN อนุญาต
2. **cookie คนส่ง** — ออก cookie ตอนอัป (ทั้ง `drop-request-upload` และ `/api/uploads` แบบ `request`), เก็บ hash
3. **รายการ + โหลด** — `toPublicRequest` คืนรายการตามโหมด, route โหลดใหม่พร้อม Range, นับยอด, rate limit, เพดานต่อวัน
4. **หน้าเว็บ** — รายการไฟล์ + พรีวิวบน `/u/...`, ตัวเลือกโหมดในฟอร์มเจ้าของ, สวิตช์ ADMIN
5. **ทดสอบ** — e2e ใหม่ `drop-requests-sharing`: ทั้ง 4 โหมด, คนอื่นไม่เห็นไฟล์ในโหมด `own`, เปลี่ยนโหมดแล้วโหลดไม่ได้ทันที,
   ลิงก์มีรหัสต้องปลดล็อกก่อน, `fileId` ของอีกลิงก์ใช้ไม่ได้, ไฟล์หมดอายุหายจากรายการ, Range/พรีวิว, เพดานต่อวัน, ADMIN ปิดโหมด
6. **เอกสาร + ขึ้นระบบ** — แก้แผนนี้เป็น "เสร็จ", README ของ e2e, ขึ้น radxa

ขั้น 1–3 เป็นฝั่งเซิร์ฟเวอร์ ทำและทดสอบด้วย API ได้ก่อน ขั้น 4 ค่อยต่อหน้าเว็บ
