# แผน: ห้องแชร์ด้วย PIN (ไม่ต้องล็อกอิน)

วันที่: 2026-11-08
สถานะ: ทำเสร็จ 2026-11-08 ยังไม่ขึ้นระบบ

## เป้าหมาย

หน้าสาธารณะหน้าเดียว (`/p`) ที่ใครก็เข้าได้โดยไม่ต้องล็อกอิน ใช้ส่งของข้ามเครื่องแบบเร็ว ๆ
เช่น อยู่หน้าคอมแล้วอยากได้ไฟล์ลงมือถือ หรือเพื่อนอยากส่งลิงก์กับรูปให้

1. เครื่องแรกกด "สร้างห้อง" ได้ PIN 4 หลัก เช่น `4821`
2. เครื่องที่สองเปิด `/p` แล้วพิมพ์ `4821` ก็เข้าห้องเดียวกัน
3. ในห้องใส่ได้สองอย่าง: **ไฟล์** กับ **โน้ต** (ข้อความ ลิงก์ในโน้ตกดได้)
4. ทุกเครื่องในห้องเห็นของที่ใส่เข้ามาแทบทันที โหลดไฟล์และก๊อปโน้ตได้
5. ห้องหมดอายุเอง ไฟล์ทั้งหมดในห้องหายไปด้วย

แอดมินเท่านั้นที่ตั้งค่าระบบนี้ได้ ผู้ใช้ทั่วไปและคนนอกตั้งอะไรไม่ได้

## 1. สิ่งที่แอดมินตั้งได้

อยู่ใน Settings → Admin หน้าใหม่ "PIN rooms"

| ค่า | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| เปิด/ปิดระบบ | ปิด | ปิดแล้ว `/p` ตอบ 404 ห้องที่เปิดอยู่ใช้ต่อไม่ได้ทันที |
| ขนาดรวมต่อห้อง (MB) | 1024 | "มากสุดต่อคน" ที่ขอมา นับรวมทุกไฟล์ในห้อง |
| ขนาดต่อไฟล์ (MB) | 1024 | ไฟล์ใหญ่ยังใช้การอัปโหลดแบบแบ่งชิ้นตัวเดิม เลยข้าม 100 MB ของ Cloudflare ได้ |
| จำนวนของต่อห้อง | 50 | นับทั้งไฟล์และโน้ต |
| อายุห้อง (นาที) | 60 | นับจากตอนสร้าง ไม่ต่ออายุเอง ตั้งได้ 5 นาทีถึง 7 วัน |
| ห้องที่เปิดพร้อมกันต่อ IP | 3 | กันคนเดียวสร้างห้องรัว ๆ |
| พื้นที่รวมของทั้งระบบ (MB) | 10240 | เต็มแล้วสร้างห้องใหม่/อัปไฟล์ไม่ได้ จนห้องเก่าหมดอายุ |

แอดมินยังเห็นรายการห้องที่เปิดอยู่ (PIN, อายุ, ขนาด, IP ที่สร้าง) และกดปิดห้องทิ้งได้

## 2. PIN และการเพิ่มหลักตามจำนวนห้อง

- เริ่มที่ 4 หลัก (0000–9999)
- ตอนสร้างห้อง ระบบสุ่ม PIN ที่ยังไม่มีใครใช้
- ถ้าห้องที่เปิดอยู่มีเกิน **1%** ของ PIN ทั้งหมดในหลักนั้น (4 หลัก = เกิน 100 ห้อง) ห้องใหม่จะได้ PIN 5 หลัก
  เกิน 1,000 ห้องก็ขึ้น 6 หลัก แบบนี้ไปเรื่อย ๆ จนถึง 8 หลัก
- ห้องเก่าใช้ PIN เดิมจนหมดอายุ พอห้องลดลง ห้องใหม่ก็กลับมาได้ 4 หลักเอง
- ช่องพิมพ์ PIN รับได้ 4–8 หลัก PIN `0042` กับ `00042` เป็นคนละห้องกัน

ทำไมต้อง 1% ไม่ใช่รอจนเต็ม: ถ้าห้องเยอะ คนที่เดา PIN มั่ว ๆ ก็มีโอกาสเข้าห้องคนอื่นได้ง่าย
คุมไว้ที่ 1% แปลว่าเดามั่ว 1 ครั้งมีโอกาสโดนห้องใดห้องหนึ่งไม่เกิน 1 ใน 100 แล้วยังมีตัวกันเดาในข้อ 3 อีกชั้น
สำหรับ NAS บ้าน ห้องคงไม่เคยเกิน 100 เลยแทบจะเป็น 4 หลักตลอด แต่โค้ดรองรับไว้แล้ว

## 3. ความปลอดภัย

PIN 4 หลักเดาง่าย เลยต้องมีตัวกันหลายชั้น

- **จำกัดการเดา**: พิมพ์ PIN ผิด 10 ครั้งใน 10 นาทีต่อ IP โดนพัก 10 นาที
  มีเพดานรวมทั้งระบบด้วย (ผิดรวม 300 ครั้งใน 10 นาที ระบบหยุดรับ PIN ชั่วคราว) กันคนใช้หลาย IP
- **เข้าห้องแล้วได้กุญแจ**: เข้าห้องสำเร็จแล้ว เบราว์เซอร์ได้ cookie ประจำห้อง (HttpOnly) ใช้ cookie นี้โหลด/อัป ไม่ต้องส่ง PIN ซ้ำ
  ลิงก์โหลดไฟล์ใช้รหัสสุ่มยาวของไฟล์ ไม่ใช่ PIN
- **ห้องอายุสั้น** (ค่าเริ่มต้น 1 ชั่วโมง) พอหมดเวลาห้องใช้ไม่ได้ทันที แล้วตัวกวาดลบไฟล์ออกจากดิสก์ภายในรอบถัดไป (ทุก 5 นาที)
- **คนสร้างห้องล็อกห้องได้**: กด "ล็อกห้อง" แล้วเครื่องใหม่เข้าไม่ได้อีก เครื่องที่อยู่ในห้องแล้วยังใช้ต่อได้ และกด "ปิดห้อง" ลบทุกอย่างได้เลย
- อัปโหลดเข้าห้องใช้ตัวกันดิสก์เต็ม (เหลือน้อยกว่า 5% ไม่รับ) กับตัวจำกัดอัตราอัปโหลดตัวเดิม
- ไฟล์ในห้องโหลดแบบ `Content-Disposition: attachment` เสมอ ไม่เปิด HTML/SVG ตรง ๆ ในเว็บเรา
  พรีวิวได้เฉพาะรูป วิดีโอ เสียง ผ่าน route เดิมที่ใช้กับ Drops
- โน้ตแสดงเป็นข้อความล้วน ลิงก์ทำเป็น `<a rel="noopener noreferrer nofollow" target="_blank">` เฉพาะ `http(s)://` ไม่รัน HTML ที่คนพิมพ์มา
- ระบบปิดอยู่เป็นค่าเริ่มต้น แอดมินต้องเปิดเอง

## 4. หน้า `/p`

- ยังไม่อยู่ในห้อง: ช่องพิมพ์ PIN ตัวใหญ่ ๆ กับปุ่ม "สร้างห้องใหม่"
- อยู่ในห้องแล้ว:
  - หัวห้องโชว์ PIN ตัวใหญ่ เวลาที่เหลือ พื้นที่ที่ใช้ไป
  - ช่องเขียนโน้ต กับที่ลากไฟล์มาวาง (แปะรูปจาก clipboard ด้วย Ctrl+V ได้)
  - รายการของในห้อง ใหม่สุดอยู่บน ไฟล์มีปุ่มโหลดและพรีวิว โน้ตมีปุ่มก๊อป
  - ใครใส่ของก็ลบของชิ้นนั้นได้ (จำด้วยกุญแจเบราว์เซอร์แบบเดียวกับโหมด `own` ของลิงก์รับไฟล์) คนสร้างห้องลบได้ทุกชิ้น
  - หน้าเช็กของใหม่ทุก 3 วินาที (polling ธรรมดา ไม่ต้องตั้ง WebSocket ผ่าน Cloudflare)
- ลิงก์ตรง `/p/4821` เปิดแล้วเติม PIN ให้เลย (ยังต้องผ่านตัวจำกัดการเดาเหมือนพิมพ์เอง)
- ข้อความบนหน้าเป็นภาษาอังกฤษเหมือนหน้าอื่นของเว็บ (รอยืนยันในคำถาม)

## 5. ข้อมูลที่เก็บ (เพิ่มอย่างเดียว ไม่แตะตารางเดิม)

ระวังเรื่อง `db push` บน radxa: ไม่มี unique constraint บนคอลัมน์ในตารางที่มีข้อมูลอยู่แล้ว
ตารางใหม่ทั้งคู่เลยใส่ unique ได้ปลอดภัย แต่จะลองกับโครงสร้างฐานข้อมูลจริงก่อนขึ้นระบบตามที่สัญญาไว้

- `PinRoom`: id, pin, creatorKeyHash, creatorIp, locked, totalBytes, itemCount, createdAt, expiresAt, closedAt
  - ห้ามมี PIN ซ้ำเฉพาะห้องที่ยังเปิดอยู่ (เช็กในโค้ดตอนสุ่ม พร้อม lock กันสร้างชนกัน) เพราะ PIN เดิมกลับมาใช้ซ้ำได้หลังห้องปิด
- `PinItem`: id, roomId, kind (`file`/`note`), fileName, size, text, shareId, senderKeyHash, createdAt, deletedAt
- ไฟล์อยู่ที่ `<ที่เก็บ drop>/.webnas-pin/<roomId>/<itemId>`
- ค่าตั้งของแอดมินเก็บใน `AppSetting` เหมือน Drops (`pin.enabled`, `pin.roomMB`, ...)
- ตัวกวาดทุก 5 นาที ลบห้องที่หมดอายุพร้อมไฟล์ (ต่อจาก sweeper ตัวเดิมใน `instrumentation.ts`)

## 6. การอัปโหลดไฟล์ใหญ่

เพิ่ม `kind=pin` ใน `/api/uploads` ตัวเดิม ฝั่งเว็บใช้ `chunkedUpload` ตัวเดิม
เช็กขนาดรวมห้อง/พื้นที่รวมระบบตอนเริ่ม จองที่ไว้ก่อน เหมือน drop request

## 7. API

| Route | ทำอะไร |
|---|---|
| `GET /api/public/pin` | ระบบเปิดไหม กับขีดจำกัดที่หน้าเว็บต้องรู้ |
| `POST /api/public/pin/rooms` | สร้างห้อง ได้ PIN + cookie คนสร้าง |
| `POST /api/public/pin/join` `{pin}` | เข้าห้อง (นับการเดา) ได้ cookie ห้อง |
| `GET /api/public/pin/room` | ข้อมูลห้อง + รายการของ (ใช้ cookie) |
| `POST /api/public/pin/room/notes` | เพิ่มโน้ต (ยาวสุด 20,000 ตัวอักษร) |
| `DELETE /api/public/pin/room/items/[id]` | ลบของ |
| `GET /api/public/pin/room/items/[id]` (+ `/raw`) | โหลด / พรีวิว |
| `POST /api/public/pin/room/lock`, `DELETE /api/public/pin/room` | ล็อก / ปิดห้อง (คนสร้างเท่านั้น) |
| `GET/PUT /api/admin/pin` + `DELETE /api/admin/pin/rooms/[id]` | ตั้งค่า / ดูห้อง / ปิดห้อง (แอดมิน) |

## 8. ทดสอบ

e2e ชุดใหม่ `pin-rooms.mjs`: ระบบปิด = 404, สร้าง/เข้าห้อง, PIN ผิดโดนพัก, เกินขนาดห้องโดนปฏิเสธ,
ไฟล์ใหญ่แบบแบ่งชิ้น, โหลดได้แค่คนที่อยู่ในห้อง, ห้องล็อกแล้วเข้าใหม่ไม่ได้, หมดอายุแล้วไฟล์หายจากดิสก์,
ขึ้น 5 หลักเมื่อห้องเกิน 1%, คนที่ไม่ใช่แอดมินแก้ค่าตั้งไม่ได้

## ตัดสินใจแล้ว (2026-11-08)

1. ทุกคนที่เข้าห้องใส่ของและโหลดได้ (สองทาง)
2. พิมพ์ PIN ถูกก็เข้าได้ มีตัวกันเดา ห้องอายุสั้น และคนสร้างล็อกห้องได้
3. ใส่ QR code บนหัวห้อง สแกนแล้วเปิด `/p/<PIN>`
4. ข้อความบนหน้า `/p` เป็นภาษาอังกฤษ

## ที่ต่างจากแผนตอนทำจริง

- ห้องที่ปิดหรือหมดอายุถูกลบทั้งแถว ไม่ได้เก็บไว้ทำเครื่องหมาย `closedAt` เลยตั้ง PIN เป็น unique ได้ตรง ๆ กันสองห้องได้ PIN ซ้ำกันในระดับฐานข้อมูล
- เครื่องในห้องจำด้วย cookie `wn_pin` ที่เซ็นด้วย `JWT_SECRET` (รหัสห้อง + กุญแจสุ่ม + ลายเซ็น) ไม่มีตารางสมาชิก เก็บแค่ hash ของกุญแจคนสร้างห้องกับคนที่ใส่ของแต่ละชิ้น
- ทุกไฟล์อัปผ่าน `/api/uploads?kind=pin` แม้ไฟล์เล็กก็ไปเป็นชิ้นเดียว ไม่มี route อัปโหลดแยก
- ทุกคำขอที่เปลี่ยนข้อมูลต้องส่งเป็น JSON ฟอร์มจากเว็บอื่นเลยพาเบราว์เซอร์คนอื่นเข้าห้องหรือสร้างห้องแทนไม่ได้
- เบราว์เซอร์หนึ่งอยู่ได้ทีละห้อง เข้าห้องใหม่ก็ออกจากห้องเก่าเอง
- หน้าเช็กของใหม่ทุก 3 วินาทีด้วยเลข `version` ของห้อง ถ้าไม่มีอะไรเปลี่ยนก็ไม่ส่งรายการกลับมา
- ปิดระบบในหน้าแอดมิน = ลบทุกห้องที่เปิดอยู่ทันที (หน้าแอดมินถามยืนยันก่อน)
